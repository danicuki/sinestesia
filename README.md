# Sinestesia

**A live AI VJ that listens to a singer and paints the stage in real time —
then mints the finished painting on-chain as a verifiable record of the
performance.**

The visuals don't cut between unrelated images. They accumulate. As the song
unfolds, one hand-drawn scene grows on screen — a sun, a castle, a glove, an
umbrella — each new element added without erasing what came before. Like the
music video for Toquinho's *Aquarela*, but generated live from whatever is being
sung. When the song ends, that exact canvas is stored on decentralized storage
and minted as a 1-of-1 NFT, with a certificate proving it was made live in that
moment — not generated after the fact.

## Why this is interesting

- **A new act for live music.** Every concert wall, festival stage, and streamed
  set is a surface. Sinestesia turns the singer's own voice into the visuals —
  no VJ, no pre-rendered loops, no two shows alike. The art is generated by the
  performance and belongs to it.
- **The performance becomes an asset.** The painting isn't a screenshot; it's a
  1-of-1 tied to a specific voice on a specific night, with the full provenance
  of how it was made. Fans can claim a print. That's a native merchandise and
  collectible primitive for artists, built into the show rather than bolted on.
- **Runs sovereign or in the cloud.** The entire creative pipeline — speech,
  the director LLM, image generation — can run on a single local machine with no
  cloud round-trip, or fan out to hosted providers. An artist can own their
  stack end to end.
- **Trust in the AI is provable.** The director LLM can run as verifiable
  inference, so the certificate can carry a cryptographic signature over the
  exact model and exchange that produced each frame — not just a claim that AI
  was involved.

## How it works

Three parallel rails listen to the mic. Each runs at a different latency budget
and feeds a different visual layer.

```
🎤 Mic
 │
 ├── Rail 1 ── Web Audio FFT/RMS ─────────► Three.js shader uniforms       (<50ms)
 │   "movement"                              (background pulse, brightness, hue)
 │
 ├── Rail 2 ── STT (ElevenLabs / Deepgram) ──► Director LLM                (~2s)
 │   "words"                                  └─► image model (img2img)
 │                                                ├─► previous image
 │                                                └─► accumulated prompt
 │                                                    │
 │                                                    ▼
 │                                              crossfade on screen        (~3-4s total)
 │
 └── Rail 3 ── Essentia.js ──► emotion/timbre features ──► (modulates Director prompts)
     "expression"                                          (mood, arousal, valence)
```

The key trick is **accumulative image-to-image**. Every new lyric line is
appended to a running multi-turn conversation with the Director LLM. Its
response is a full prompt describing the *entire current drawing* including every
element added so far. That prompt is fed to an img2img model with the **previous
image as the input**, so the model gently nudges an existing canvas rather than
generating from scratch. The visual identity persists across the whole song.

When the song ends, the final canvas is stored on **Walrus** (decentralized
storage) and minted on **Sui** as a 1-of-1 to the artist plus an open print
window fans can claim. The mint carries a provenance certificate: the full
director conversation, per-turn timestamps and models, and — when the Director
ran on verifiable inference — the signature proving which sealed model produced
each prompt.

The details that took the most iteration to get right — the bootstrap gate,
multi-turn caching, output validation, session invalidation — are written up in
**[HANDOFF.md](HANDOFF.md)**.

## Stack

- **Director (the LLM that decides what to draw)**: pluggable. Defaults to
  **Gemma 12B running locally via Ollama** — sovereign, on-device AI in the
  critical path of a live performance, no cloud round-trip — with a fallback
  chain to Gemini and Claude Haiku. Can also run as **verifiable inference on 0G
  Compute**, where each prompt is signed by the provider against the exact model.
- **STT**: ElevenLabs Scribe v2 Realtime as primary, Deepgram Nova-3 as A/B
  alternative, local Whisper for a fully offline stack. Toggle with
  `STT_PROVIDER`. Multilingual.
- **Image gen**: pluggable — fal.ai Flux (img2img + Schnell), Cloudflare,
  Google, Pollinations, or a local SDXL sidecar.
- **On-chain**: **Sui** (Move contract: 1-of-1 master + open-edition prints) and
  **Walrus** for the artwork bytes. Minting runs from a small Node sidecar
  (`sui/mint`); the public claim page is a serverless deployment of the same
  code.
- **Verifiable inference**: **0G Compute** sidecar (`zerog`) routes the Director
  through TEE-signed inference and resolves the proof artefacts per chat.
- **Backend**: Elixir/OTP. Bandit + Plug + WebSockAdapter (no Phoenix).
  Mint.WebSocket for outbound streaming clients. Per-session GenServer
  orchestrates the rails.
- **Frontend**: Vite + TypeScript + Three.js + Essentia.js.

## Why Elixir?

Three streaming clients (browser PCM, ElevenLabs STT, Deepgram STT) and three
async pipelines (Director task, image gen task, style curator task) per session.
Each rail needs independent supervision, backpressure, and clean session reset.
OTP is the right tool — `Task.start` per rail, MapSet of in-flight PIDs in state,
`Process.exit(pid, :kill)` on reset to stop paying for old work. The whole
orchestrator is one GenServer.

## Run it locally

```bash
# 1. Local Director (Gemma via Ollama)
ollama serve &
ollama pull gemma4:12b-mlx

# 2. Env vars
cp .env.example .env
# fill in ELEVENLABS_API_KEY and FAL_API_KEY (others optional)

# 3. Backend
cd backend && mix deps.get && mix run --no-halt

# 4. Frontend (separate terminal)
cd frontend && bun install && bun run dev

# 5. Open http://localhost:5173 in Chrome, allow mic, sing.
```

The `.env` lives at project root and is loaded by `Sinestesia.Application`.
Minting and verifiable inference are optional add-ons with their own `.env` files
under `sui/mint` and `zerog` — the show runs without them.

### 🎬 Headless replay & video compilation

You can headlessly replay any recorded session JSON (under `tests/sessions/`)
through the full pipeline (including Director and image generation) to export a
finished sequence and compile a synchronized MP4:

```bash
# Replay a session at 20x speed to fetch and generate frames rapidly
REPLAY_SPEED=20 mix sinestesia.replay ../tests/sessions/jorge-vercilo---homem-aranha.json --slug homem-aranha
```

The task exports all generated frames and updates
`frontend/public/samples/index.json`.

- **Interactive audio sync**: `http://localhost:5173/?demo=homem-aranha` shows a
  custom glassmorphic audio player that keeps the Three.js crossfade transitions
  in lockstep with the song's playhead during playback and scrub.
- **Synchronized MP4**: the task compiles a high-compatibility H.264/AAC video
  (`video.mp4` in the sample directory) with `ffmpeg`. If a song opens with a
  long instrumental, the video starts with a matching blank canvas, then rapid
  synthetic crossfades aligned to the song's real timeline.

### ⚙️ Configuration

Sinestesia is highly configurable, supporting both cloud-bound and 100% offline
local AI stacks. Configuration is managed via the `.env` file at the project
root.

**To see what a machine is actually running**, don't read a table — ask it. The
backend prints its entire configuration at boot, marking every value that came
from the environment rather than a default, and serves the same thing live:

```bash
curl localhost:4000/config?format=text   # the boot banner
cd backend && mix sinestesia.config      # the same, without booting anything
```

API keys are never printed, only whether they are set.

> [!TIP]
> Every variable, with defaults and accepted values, is in
> **[CONFIGURATION.md](CONFIGURATION.md)** — generated from
> `backend/lib/sinestesia/config.ex`, so it can't drift from the code.

The five you'll toggle most:

| Environment Variable | Default | Options / Profiles | Description |
| :--- | :--- | :--- | :--- |
| **`STT_PROVIDER`** | `elevenlabs` | `elevenlabs` \| `deepgram` \| `both` \| `local_whisper` \| `replay` | Speech-to-text service used to transcribe real-time vocals. |
| **`DIRECTOR_PROVIDER`** | `gemma` | `gemma` (local) \| `gemini` \| `haiku` \| `zerog` (verifiable) | LLM that compiles the accumulative scene description. Picks the *provider*: `OLLAMA_MODEL` only applies when it is `gemma`. |
| **`IMAGE_PROVIDER`** | `fal` | `fal` \| `cloudflare` \| `google` \| `pollinations` \| `local_sdxl` | Who renders the stage canvas. |
| **`RENDER_MODE`** | `i2i` | `i2i` (evolve the previous frame) \| `t2i` (render each frame fresh) | Independent of the provider — they all do both. `i2i` buys continuity at several seconds per frame; `t2i` is faster and never drifts. |
| **`IMAGE_MODE`** | `story` | `story` (accumulative canvas) \| `classic` (independent frames) | If `story`, drawings morph and accumulate lyric elements sequentially. |
